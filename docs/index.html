Zen Site Security — HTTPS, headers and hardening

Getting a certificate is the easy part. Migrating WordPress onto it without breaking the site, keeping it there, noticing before it expires, and hardening what sits behind it — that is the work. Zen Site Security does all of it, and refuses to activate until a valid certificate is genuinely installed, so you cannot lock yourself out by accident.

One click to HTTPS — and a way back

Activation verifies the certificate first, then switches your site and home URLs to https, 301-redirects every HTTP request, and rewrites mixed content on the fly.

✓It checks before it switches

The certificate is probed directly and parsed — issuer, expiry, and whether it actually covers your domain, wildcards included. Activation is blocked until a valid certificate is found, because the failure mode of getting this wrong is an unreachable site.

↪Redirects, your way

A PHP 301 redirect by default — works on every server and disappears the moment the plugin is deactivated. Optional .htaccess rules for Apache and LiteSpeed, written above the WordPress block in marked, removable blocks. On nginx you get the exact server snippet to paste.

⚭Mixed content, fixed

Insecure references to your own site — including www and non-www variants and JSON-escaped URLs — are rewritten just before the page is sent. Feeds, sitemaps and JSON responses are left alone. An opt-in fixer covers wp-admin too.

⏱It tells you before it expires

A daily background check re-probes the certificate independently of admin visits and emails you when fewer than 15 days remain — so an expiring certificate is caught even if nobody logs in that week.

◈A TLS grade, not just a tick

A letter grade with specific findings for the negotiated protocol, key strength, signature algorithm, cipher and chain — shown on the settings page and the Dashboard widget, with a link out to SSL Labs for a full protocol audit.

⚑An escape hatch that always works

One line in wp-config.php — define( 'ZENSS_DISABLE_SSL', true ); — reverts the URLs to http, disables the redirect and strips the .htaccess rules on the very next request. No admin access required.

Then harden what sits behind it

Every hardening control is opt-in, and every header stands down automatically if another plugin already sends it.

ControlWhat it does
Security headers X-Content-Type-Options, X-Frame-Options, Referrer-Policy, a conservative Permissions-Policy and CSP upgrade-insecure-requests. Optionally written into .htaccess so static files and non-WordPress responses are covered too.
Strict CSP An advanced, opt-in Content-Security-Policy that stamps a per-request nonce on WordPress-rendered scripts and ships 'strict-dynamic'. Report-Only by default, with a violations panel and a one-click Allow button for each source you recognise.
HSTS Opt-in Strict-Transport-Security, starting at a one-day max-age for safe testing. The preload-eligible configuration needs an explicit second opt-in, because it is hard to undo.
SameSite cookies WordPress auth cookies are re-issued with an explicit SameSite=Lax attribute, so CSRF protection no longer depends on browser defaults — a second layer beside nonces.
Cache deception defence Logged-in pages and authenticated REST responses are marked no-store, private, and a dynamic response is never allowed to be cached under a static-looking URL — the origin-side defence OWASP recommends.
Attack-surface reduction Disable the wp-admin file editors, block PHP execution in uploads (an uploaded webshell becomes a dead file), deny web access to logs, dumps, backups and wp-config variants, turn off directory listings and XML-RPC, and hide the WordPress version and X-Powered-By.
security.txt Optional RFC 9116 disclosure file served on the fly at /.well-known/security.txt — nothing written to disk, so it never clashes with Let's Encrypt challenges.
Score & Site Health A Dashboard security score with your top recommended next steps and a one-click "enable recommended protections", plus the same posture surfaced as tests under Tools → Site Health. One engine drives both, so they always agree.

Honest limits

Security plugins are the easiest category in which to overpromise. To be clear about what this does not do:

  • It does not issue certificates. Your host does that — most offer free Let's Encrypt certificates in their control panel. This plugin detects the certificate and migrates WordPress onto it.
  • It cannot patch a vulnerability in another plugin. Nothing can. What it does is defence in depth: headers that make XSS harder to exploit, SameSite cookies that blunt CSRF, and hardening that turns many exploit paths into dead ends.
  • There is no regex "firewall". Pattern-matching request filters that claim to block SQL injection or XSS are bypass-prone, break real sites, and are not built here on purpose.
  • Version 1.x targets single-site installs. Multisite support is planned.
Deactivating the plugin does not push you back to http. The .htaccess rules are removed and the PHP redirect stops, but your site URLs deliberately stay on https — turning off a plugin should never downgrade a working secure site. Use Revert site to HTTP on the settings page if that is genuinely what you want.
